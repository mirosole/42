# Push_swap - план проекта

## 1. Главная задача

Программа получает список уникальных целых чисел. Все числа изначально находятся
в стеке `a`, а стек `b` пустой. Нужно отсортировать `a` по возрастанию, используя
только разрешенные операции push_swap. В конце `a` должен быть отсортирован, а
`b` - пустым.

```bash
./push_swap 2 1 3 6 5 8
```

Программа печатает только операции, по одной на строке.

## 2. Два стека

```text
a - основной стек с числами
b - вспомогательный стек, изначально пустой
```

Первый аргумент считается верхушкой стека `a`:

```text
a: 4 2 7
```

Число `4` находится сверху.

## 3. Разрешенные операции

```text
sa  - поменять два верхних элемента a
sb  - поменять два верхних элемента b
ss  - одновременно выполнить sa и sb

pa  - перенести верхний элемент из b в a
pb  - перенести верхний элемент из a в b

ra  - первый элемент a переместить в конец
rb  - первый элемент b переместить в конец
rr  - одновременно выполнить ra и rb

rra - последний элемент a переместить в начало
rrb - последний элемент b переместить в начало
rrr - одновременно выполнить rra и rrb
```

## 4. Общий flow программы

```text
argv
  -> разбор флагов и чисел
  -> проверка ошибок
  -> создание стека a
  -> создание пустого стека b
  -> вычисление disorder
  -> выбор алгоритма
  -> сортировка через операции push_swap
  -> печать операций в stdout
  -> benchmark в stderr, если включен --bench
```

Подробные шаги:

1. Прочитать аргументы командной строки.
2. Найти флаги `--simple`, `--medium`, `--complex`, `--adaptive`, `--bench`.
3. Остальные аргументы преобразовать в числа.
4. Проверить диапазон `int`, корректность формата и отсутствие дубликатов.
5. Заполнить `a` и создать пустой `b`.
6. Посчитать disorder до выполнения любых операций.
7. Выбрать стратегию сортировки.
8. Выполнить операции над стеками.
9. Убедиться, что `a` отсортирован, а `b` пуст.
10. Напечатать операции.

## 5. Проверка входных данных

Нужно обрабатывать:

- нечисловые аргументы;
- выход за пределы `int`;
- дубликаты;
- пустые строки;
- неправильные флаги.

При ошибке в `stderr` печатается:

```text
Error
```

Если аргументов нет, программа ничего не печатает.

## 6. Disorder

Disorder показывает, насколько исходный стек далек от сортировки:

```text
0.0 - стек уже отсортирован
1.0 - максимально возможный беспорядок
```

Для каждой пары элементов проверяем, находится ли большее число перед меньшим:

```text
mistakes = 0
total_pairs = 0

для каждого i:
    для каждого j после i:
        total_pairs++
        если a[i] > a[j]:
            mistakes++

disorder = mistakes / total_pairs
```

Disorder обязательно вычисляется до начала сортировки.

## 7. Четыре стратегии

### Simple - O(n^2)

Базовый алгоритм. Возможный вариант: искать минимальный элемент, подводить его
к вершине через `ra` или `rra`, переносить в `b`, а затем возвращать элементы в
`a`. Подходит для маленьких и почти отсортированных входов.

### Medium - O(n*sqrt(n))

Chunk-based алгоритм. Диапазон индексов делится примерно на `sqrt(n)` частей.
Элементы текущего диапазона переносятся в `b`, после чего возвращаются в `a` в
нужном порядке.

### Complex - O(n log n)

Рекомендуемый вариант - radix sort. Сначала значения нормализуются в индексы:

```text
-100  5  42  999
   0  1   2    3
```

Затем числа сортируются по битам:

```text
если текущий бит равен 0: pb
иначе:                    ra

после прохода: pa, пока b не пуст
```

### Adaptive

Алгоритм сначала считает disorder и выбирает стратегию:

```text
disorder < 0.2         -> Simple
0.2 <= disorder < 0.5  -> Medium
disorder >= 0.5        -> Complex
```

`Adaptive` используется по умолчанию, если стратегия явно не указана.

## 8. Флаги запуска

```bash
./push_swap --simple 2 1 3
./push_swap --medium 2 1 3
./push_swap --complex 2 1 3
./push_swap --adaptive 2 1 3
./push_swap --bench --complex 4 67 3 87 23
```

Без флага используется `--adaptive`.

## 9. stdout и stderr

Операции печатаются в `stdout`:

```text
ra
pb
pa
```

Benchmark печатается в `stderr` и содержит disorder, стратегию, сложность,
общее количество операций и количество каждой операции.

```bash
./push_swap --bench 4 67 3 87 23 > operations.txt 2> benchmark.txt
```

Так операции можно отправить в checker:

```bash
./push_swap 4 67 3 87 23 | ./checker 4 67 3 87 23
```

## 11. Назначение модулей

- `main.c` - запускает весь flow программы.
- `parser.c` - разбирает числа и флаги.
- `validation.c` - проверяет ошибки, диапазон `int` и дубликаты.
- `stack.c` - создает и освобождает стеки.
- `operations_*.c` - реализуют все операции push_swap.
- `disorder.c` - вычисляет disorder до сортировки.
- `normalize.c` - переводит значения в ранги для radix sort.
- `strategy.c` - выбирает стратегию.
- `simple.c`, `medium.c`, `complex.c`, `adaptive.c` - алгоритмы сортировки.
- `benchmark.c` - собирает статистику и печатает ее в `stderr`.

Алгоритмы не должны напрямую ломать структуру списков. Они должны пользоваться
функциями операций (`sa`, `pb`, `ra` и т.д.).

## 12. Возможные структуры данных

```c
typedef struct s_node
{
    int             value;
    int             index;
    struct s_node   *next;
} t_node;

typedef struct s_stack
{
    t_node  *top;
    int     size;
} t_stack;

typedef struct s_program
{
    t_stack a;
    t_stack b;
    double  disorder;
    int     operation_count;
} t_program;
```

## 13. Checker - bonus

`checker` читает исходные числа и операции из `stdin`, применяет операции и
проверяет результат.

Если `a` отсортирован, а `b` пуст, печатает `OK`. В противном случае печатает
`KO`. Некорректные аргументы или неизвестные операции дают `Error` в `stderr`.

Проверка:

```bash
./push_swap 4 67 3 87 23 | ./checker 4 67 3 87 23
```

## 15. Главное разделение проекта

```text
Уровень 1: механика стеков
sa, sb, ss, pa, pb, ra, rb, rr, rra, rrb, rrr

Уровень 2: алгоритмы сортировки
Simple, Medium, Complex, Adaptive
```

Операции изменяют стеки. Алгоритмы решают, какие операции и в каком порядке
нужно вызвать.

Итоговый flow:

```text
input -> parse -> validate -> create a -> create b
      -> compute disorder -> choose strategy
      -> call stack operations -> a sorted, b empty
      -> print operations
```
